# LightShow 2.0 — частицы, формулы, текст, рисовалка

Spigot/Paper **1.16.5**, Java 8+. Готовый jar: `LightShow-2.0.0.jar`.

---

## Почему раньше всё выглядело плохо (и что исправлено)

**1. Работал только знак бесконечности.**
Старый парсер считал `cos(t)^3` как `cos(t^3)` — классическая ошибка того парсера со StackOverflow.
Поэтому астроида, роза, сердце превращались в мусор, а бесконечность (без степеней) — работала.
Теперь степень применяется к готовому атому: `cos(t)^3 = (cos t)³`. Проверено тестом.

**2. Каша и «дублирование» частиц при движении.**
Было: `spawnParticle(END_ROD, loc, 1, 0.05,0.05,0.05, speed)`.
При `count = 1` offset — это **случайный разброс**, а `speed` — **случайная скорость**. Частицы разлетались,
и каждый тик поверх них рождались новые → каша.
Стало: `count = 0`. Тогда клиент рождает **ровно одну** частицу, а `(dx,dy,dz)` становится
**вектором скорости**, умноженным на `speed`. Хочешь неподвижную точку — всё по нулям, и картинка стоит как вкопанная.

**3. Анимация «пропадала».**
Клиент сам вырезает частицы дальше **32 блоков**, если в пакете не стоит флаг longDistance.
Шоу в небе физически не долетало до глаз. Теперь флаг стоит всегда, а пакеты отправляются
адресно только тем, кто в радиусе `view:`.

**4. Про end_rod, чтобы больше не удивляться.**
У end_rod время жизни ~60–72 тика и слабая гравитация — он медленно **проседает вниз**.
Поэтому «почаще спавнить» не всегда хорошо: за 60 тиков накопится 60 копий каждой точки,
клиент захлебнётся и начнёт их выбрасывать (то самое мигание).
Правильный ответ — параметр `refresh:` (раз в сколько тиков обновляется точка) плюс
**распределение по тикам**: точки разбиты на группы, каждый тик отправляется только одна группа.
Нагрузка ровная, картинка сплошная.
`refresh:1` — максимально плотно и ярко, `refresh:3` — красиво и дёшево, `refresh:5-10` — для огромных фигур.
Если нужна идеально висящая фигура без просадки — бери `particle:dust` (не падает + любой RGB).

**5. Всё было временное.**
Теперь `dur:30s`, `dur:5m`, `dur:inf`, `loop:true`, плюс постоянные **ambient**-шоу,
которые сохраняются на диск и сами поднимаются после рестарта сервера.

## Формулы

```
/pshow new <имя> <формула> [| второй слой | третий ...] [ключ:значение ...]
```

Внутри формулы:

| | |
|---|---|
| Переменные | `t` — параметр, `u` — второй параметр, **`T` — секунды с начала шоу**, `p` — прогресс 0..1, `i`/`n` — номер точки и их число |
| Свои переменные | `let r=4+sin(T*3); x=r*cos(t); y=r*sin(t)` |
| Функции | sin cos tan asin acos atan atan2 sinh cosh tanh sqrt cbrt abs sign floor ceil round frac exp ln log min max pow hypot mod clamp lerp step smooth ease saw tri sq pulse noise rand if **step4** |
| Константы | `pi tau e phi` |
| Сравнения | `if(t<pi, 1, -1)` |

`step4(k)` — плавно щёлкает по целым числам. Именно на нём сделан зрачок,
который смотрит в 4 стороны: `let a=step4(T*0.5)*pi/2;` → 0°, 90°, 180°, 270° с мягким переходом.

### Несколько формул в одной анимации

Слои разделяются `|`, у каждого слоя могут быть **свои** параметры после `@`:

```
/pshow new glaz x=7*cos(t);y=2.6*sin(t)*cos(t) @ color:aqua steps:400 | let a=step4(T*0.5)*pi/2; x=1.8*cos(t)+2.6*cos(a); y=1.8*sin(t)+0.85*sin(a) @ color:white particle:end_rod
```

А ещё можно склеивать готовые пресеты прямо в команде:

```
/pshow play demon_eye+aura+koltso dist:14 dur:inf
```

### Режимы отрисовки `mode:`

* `curve` — линия по `t` (по умолчанию)
* `tube` — **труба** вокруг линии: `radius:1.5 sides:22` → коридор шириной 3 блока, по которому реально ходят
* `surface` — поверхность по `t` и `u`: сферы, торы, волны
* `fill` — заливка фигуры от центра (`u` = 0..1)

```
/pshow new koridor x=9*cos(t);y=1.4*t;z=9*sin(t) mode:tube radius:1.5 sides:22 t:0..25 steps:700 dur:inf
```

## Полёт частиц (то, что ты имел в виду под to_player)

`motion:` задаёт **направление скорости** частицы, `mspeed:` — её величину. Работает лучше всего на `end_rod`.

`none` `out` `in` `up` `down` `flow` (вдоль кривой) `spin` `to_player` `from_player` `look` `random` `vec:0,1,0`

```
/pshow play koltso motion:to_player mspeed:0.4     # кольцо стреляет лучами в лицо
/pshow play portal_luch                            # столб света вверх
/pshow play koltso motion:flow mspeed:0.15         # частицы бегут по кругу
```

`lift:0.01` — лёгкий подъём против гравитации end_rod, если фигура «оседает».

## Текст

```
/ptext ПРИВЕТ МИР size:2 font:bold color:rainbow in:type out:scatter dur:25s
/pshow text welcome Добро_пожаловать font:pixel px:0.3   # сохранить как пресет
```

* **Шрифты**: `pixel` (8×16, компактный, идеален для частиц), `bold`, `thin` — встроены в jar,
  **кириллица работает всегда**, даже если на сервере нет ни одного системного шрифта.
  Плюс любой системный: `/pshow fonts`.
* `px:` — размер одного пикселя буквы в блоках, `size:` — общий масштаб, `align:` left/center/right, `\n` — перенос строки.
* **Несколько строк**: пиши `\n` между строками, а расстояние задавай сам — `lgap:0` (вплотную),
  `lgap:3` (обычно), `lgap:8` (просторно). Каждая строка обрезается отдельно, так что интервал реальный.
* `spacing:` — расстояние между буквами, `outline:true` — только контур букв (имеет смысл для `font:bold`).
* В шрифты встроены символы ♥ ★ ✦ ● ■ → ← ↑ ↓ № — их можно писать прямо в тексте.
* **Появление** `in:` — `fade type wipe rise drop explode scale spiral`
* **Исчезновение** `out:` — `fade scatter fall dissolve wipe implode shrink`
* Длительности: `int:20t`, `outt:1s`

Анимации появления/исчезновения работают **для любых** шоу, не только для текста.

## Рисовалка `/pshow draw <имя>`

Холст 9×4 (36 слотов) белыми стеклянными панелями, нажатая = светится (скрытый энчант).

* **рисовать протягиванием мыши**, а не тыкать по клетке;
* ПКМ — стереть;
* **кадры**: `◀ ▶` листают, бумага — дублировать / удалить / очистить → получается **покадровая анимация**;
* нижняя строка: частица, цвет, размер пикселя, полёт частиц, скорость кадров, предпросмотр;
* зелёный бетон — сохранить в пресеты.

```
/pshow play mylogo spin:45 dur:inf fps:2
```

## Сцены: у каждого слоя свой таймлайн

Шоу — это не одна картинка. Каждый слой живёт по своему расписанию:

```
from:3s     слой появляется на третьей секунде
to:9s       и исчезает на девятой
in: out: int: outt:   тоже задаются НА СЛОЙ — у каждого элемента свой вход
```

А положение и размер слоя можно писать **формулой от T** (секунды с начала шоу):

```
ox: oy: oz:   смещение слоя
zoom:         масштаб слоя
```

Стандартный разгон — `smooth((T-A)/B)`: ноль до секунды A, за B секунд доезжает до единицы.

```
ox:-5-lerp(0,4,smooth((T-3)/1))         стоит на -5, на 3-й секунде за секунду уезжает на 4 блока влево
oy:12-lerp(0,12,smooth(T/1.2))          падает с 12 блоков сверху на место за 1.2 секунды
zoom:lerp(0.25,1.9,smooth((T-6)/1.5))   растёт с 25% до 190% между 6-й и 7.5-й секундой
```

Пример сцены целиком — два ника, один падает на другой, потом они разъезжаются и между ними растёт сердце:

```
/pshow text sc_a aitcHinson px:0.25 ox:-5-lerp(0,4,smooth((T-3)/1)) in:fade int:15t
/pshow text sc_b AlliSighs px:0.25 oy:12-lerp(0,12,smooth(T/1.2)) ox:5+lerp(0,4,smooth((T-3)/1)) from:10t in:fly int:25t
/pshow new sc_h let s=0.3;x=s*16*sin(t)^3;y=s*(13*cos(t)-5*cos(2*t)-2*cos(3*t)-cos(4*t)) @ steps:200 from:4s in:scale int:20t zoom:lerp(0.25,1.9,smooth((T-6)/1.5))
/pshow play sc_a+sc_b+sc_h dist:14 dur:25s
```

`dur:` на запуске должен покрывать весь сценарий, иначе поздние слои просто не успеют.

Ещё на слой:

* `rotx: roty: rotz:` — наклон и вращение слоя в градусах, тоже формулами (`rotz:T*60` — крутится, `rotz:10*sin(T*2)` — качается)
* `every:2s for:0.6s` — слой повторяется циклами: вспыхивает на 0.6 секунды каждые 2 секунды, со своей `in:`/`out:` внутри каждой вспышки
* `sound:block.beacon.activate svol:1 spitch:1.2` — звук в момент появления слоя (и на каждом повторе)

## ИИ собирает шоу за тебя

```
/pshow ai красивая луна в форме отрезанного бублика, вокруг падают метеориты, у ног искры
```

Приходят **3 варианта**. Для каждого плагин заранее компилирует все формулы и считает точки и
пакеты в тик — если ИИ намудрил, ты увидишь предупреждение до запуска, а не тормоза.

```
/pshow ai run 1              создать пресеты и запустить
/pshow ai show 1             показать команды варианта
/pshow ai fix 1 сделай луну крупнее и убери метеориты
/pshow ai del 1              удалить созданные пресеты
```

Модель знает язык формул, лимиты нагрузки и правило «основа — end_rod, dust только точечно».

## Эмиттеры: метеоры, дождь, искры

Статичная точка, которая плюёт частицей вниз, — это мерцающий столбик, а не звездопад.
Настоящий эмиттер: мало точек спавна, редкий вылет, своя скорость и хвост.

| | |
|---|---|
| `vx: vy: vz:` | скорость частицы в **мировых** осях, блоков за тик. Формулы от `i` (номер точки), `u` (номер цикла вылета) и `T` |
| `trail:7 tgap:0.45` | хвост позади головы — именно он превращает точку в метеор |
| `jitter:14` | точка спавна прыгает случайно при каждом вылете, ничего не «висит» |
| `chance:0.55` | точка стреляет только в 55% своих очередей — рваный живой ритм |
| `refresh:45` | каждая точка стреляет раз в 45 тиков, вылеты сами размазываются по тикам |
| `count:4 spread:0.5` | несколько частиц ОДНИМ пакетом — для облаков, тумана, дыма |

Частица пролетает примерно `|v| × 35` блоков за жизнь, так что `vy:-0.6` — падение на 21 блок.

```
/pshow new stars let a=noise(i*.13)*70;let c=noise(i*.71+9)*70;x=a;y=34+noise(i*.37+3)*10;z=c @ steps:36 refresh:45 jitter:14 chance:0.55 vx:0.42+0.2*noise(i*.9+u) vy:-0.62 vz:0.18*noise(i*.5+u) trail:7 tgap:0.45
/pshow play stars face:north cull:0 view:128 dur:inf
```

36 точек спавна, 3.6 пакета в тик, 217 живых частиц на весь звездопад.

## Постоянные шоу (ambient)

```
/pshow ambient add spawn_eye demon_eye dist:15 dur:inf view:64
/pshow ambient list
/pshow ambient del spawn_eye
```

Сохраняются в `ambient.yml`, поднимаются сами при старте сервера.
Пока рядом нет игроков — шоу **вообще не считается и не шлёт пакетов**, TPS не трогает.

## Производительность — читай, это важно

Частица `end_rod` живёт у клиента **~60 тиков**. Значит:

```
живых частиц у игрока = точек × 60 ÷ refresh
пакетов в тик         = точек ÷ refresh
```

900 точек при `refresh:2` — это **27 000 живых частиц** у каждого клиента и 9000 пакетов в секунду.
Отсюда и просадка FPS, и таймауты пинга. Правильно наоборот:

* **статичная фигура** → `refresh:12…20`. Точка обновляется редко, но частица ещё жива — картинка сплошная.
  За 20 тиков end_rod проседает от гравитации на 0.1 блока, глазом не видно.
* **что-то движется** (зрачок, вращение, `spin:`) → `refresh:3…6`, иначе останется шлейф от старых позиций.
* Плагин ставит это сам: статичный слой — 12, анимированный — 3. `refresh:` задаётся **на каждый слой** отдельно.

Остальное:

* `cull:40` — точки дальше 40 блоков от игрока вообще не отправляются. Для длинных штук
  (спиральный коридор, ДНК на 25 блоков) это разница между 400 и 60 пакетами в тик.
* `max-particles-per-tick` в `config.yml` — общий потолок на сервер, делится между шоу.
* Статичные фигуры считаются один раз; пересчитываются только слои с `T`/`p`/`rand`.
* Пакеты уходят только игрокам в радиусе `view:`, прямым NMS-пакетом.
* **dust дороже end_rod** и по трафику, и по отрисовке. Используй его точечно: редкие цветные
  искры, где точек десятки, а не тысячи. Вся основа — `end_rod`.

Игрокам напомни выставить **Настройки → Графика → Частицы: Все**.

## Использование в своём плагине

LightShow — не только плагин с командами, но и библиотека. Всё, что умеют команды, доступно из Java.

```java
LightShowAPI lights = LightShowProvider.require();

ShowHandle h = lights.show()
        .formula("x=4*cos(t);y=4*sin(t)").particle("end_rod").refresh(15).and()
        .near(player, 6)
        .duration(20 * 10)
        .onlyFor(player)          // видит ровно один игрок
        .start();
```

Есть аудитории (per-player, по правам, по условию), управление шоу на лету (`move`, `setPaused`,
`setAudience`, `setDurationTicks`), отменяемые события `ShowStartEvent`/`ShowEndEvent`,
реестр пресетов, свои функции для языка формул и рендер текста в пиксели.

Частицы уходят адресно: сначала прямым NMS-пакетом, если не вышло — через ProtocolLib,
и только в крайнем случае обычным Bukkit API (там показ одному игроку становится приблизительным).
Проверяется через `lights.transport()`.

Полная документация: **LIGHTSHOW-API.md**. Язык формул и параметры: **LIGHTSHOW-LLM-REFERENCE.md**.
